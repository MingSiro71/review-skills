# 観点1: 変更箇所そのもののロジック誤り

- **入力**: diff
- **採点**: バグ列（実運用で踏む頻度と、機能への影響で採点される）

## 担当

diff を読めば判定できる誤り。

- 条件分岐の抜け、条件の反転、境界値
- null / undefined / 空配列の扱い
- 早期 return やガードの順序
- 演算・比較・型変換の誤り
- 例外経路、失敗時の戻り値

## 担当外

呼び出し元・既存データ・変更前の挙動を調べて初めて言えることは**観点2 の担当**。
裏を取るために diff の外へ出る必要が生じたら、それは観点2 の領域なので報告しない。

可読性・命名は観点8。パフォーマンスは観点3。
