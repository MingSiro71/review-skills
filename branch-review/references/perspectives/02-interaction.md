# 観点2: 既存の呼び出し元・既存データ・過去の挙動との相互作用

- **入力**: diff ＋ 呼び出し元 ＋ 既存データが取りうる条件
- **採点**: `scoring/bug.md`（実運用で踏む頻度と、機能への影響で採点される）

## 担当

diff だけでは見えない誤り。次を**実際に読みに行くこと**。

- この変更が呼ばれている箇所すべて。引数・戻り値・副作用について呼び出し元が置いていた前提が崩れていないか
- 既存データが取りうる値。過去に保存されたレコード、初期化されていないカラム、null を含む行、
  一括取込など通常フロー以外の経路で作られたデータ
- 変更前の挙動。削除・置換された実装が何を保証していたか。その保証が新実装で失われていないか
- 日付・権限・設定・機能フラグなど、実行時の条件で分岐が変わるもの。過去日・未来日、権限の薄い利用者、
  設定が未作成の状態で何が起きるか

## この観点の位置づけ

1体に「バグを探せ」と言うと、diff の中で済む安い指摘に流れる。この観点は明示的に外へ出る担当として
置かれている。過去の実績で本当に対応が必要だった指摘は、いずれもこの型だった。

裏取りを省略した推測は提出しない。「〜の可能性がある」で止まっているものは、成立条件を実コードで
特定できるまで掘るか、落とす。

## 担当外

「diff の中だけを見て言えること」は**観点1 に任せ、報告しない。**
