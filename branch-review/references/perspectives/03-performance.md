# 観点3: パフォーマンス

- **入力**: diff
- **採点**: `scoring/bug.md`（頻度で採点される。実運用で到達しない経路は0点になる）

## 担当

可読性を犠牲にしない範囲での改善。

- N+1、ループ内のクエリ・同期処理
- 不要な再計算、キャッシュされていない再構築
- 過剰な fetch、表示に寄与しないリソースの定期取得
- 不要な全件走査、同じ列挙の重複

## 必ず示すこと

**何回・どれだけ余分に走るかを具体的な数で示す。** 頻度と規模を示せないものは提出しない。
「非効率に見える」だけでは失敗シナリオが書けない。

## 担当外

可読性を犠牲にする最適化は提案しない。それは改善案が現行案より優れているかの検証で落ちる。
コードの重複そのものは観点8。
