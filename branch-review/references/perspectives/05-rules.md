# 観点5: 明文ルールとの照合

- **入力**: 起動プロンプトで渡された `RULE_FILES` のうち、この変更に関係するものだけ
- **採点**: 規約列

## 担当

**明文化されたルールへの違反だけ。**

## 必須

指摘には、根拠にしたルールの**本文を1行だけ引用**し、どのファイルのどの記述かを明記する。
引用できないものは提出しない。

評価担当が引用元を読み直し、その記述が本当にこの件を明示しているかを確認する。
明示していない引用は却下される（似た趣旨の記述があるだけ、推奨・努力目標として書かれているだけ、
の場合も水準に届かない）。

## 担当外

- 「慣例」「他のファイルではこうしている」は明文ではないので扱わない。
  読みにくさとして扱えるなら観点8 の担当。
- 手順書（コマンドの実行方法、環境変数の設定、事務手続きの説明）は照合先にしない。
  照合先になるのは、コードがこうあるべきと定めている記述だけ。
- linter / typechecker / compiler が捕まえるものは扱わない（`false-positives.md`）。
- ルールに反しているが、コード上で明示的に黙らせているもの（lint ignore コメント等）は扱わない。
