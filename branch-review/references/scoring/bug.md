# 採点基準: バグ列

**対象**: 観点1・2・3・4。および観点6・7 のうち、テストの欠落（この変更で新たに到達可能に
なった経路が踏まれていない等）と、テストが誤りを見逃す性質のもの（条件によって素通りする
アサーション、実データでは成立しないフィクスチャ）。

観点6・7 のテスト関連は「そのテストが無いことで通り抜けるバグの大きさ」で採点する。

## 採点

「**その指摘を落としたとき、誰が、いつ、どんなコストを払うか**」を言葉で書かせた上で、
そのコストの大きさを下の5水準で採点する。

| 点 | 基準 |
| --- | --- |
| 0 | 実運用で到達しない経路 |
| 25 | 起こりうるが、成立条件を具体的に示せていない |
| 50 | 稀な条件でのみ発生し、影響も局所的 |
| 75 | 日常操作で踏む。誤った値の表示・保存など機能に直接影響する |
| 100 | 通常操作で必ず踏む。データ破壊・実行時エラー |

## 守ること

- **他の列（設計・可読性 / 規約）と比較しない。** この列の中での強さだけを測る。
  列を跨いだ優先順位は統合側の並び順が持つ。
- **深刻度の自己申告を採点に使わない。** 高/中/低 は書き手のラベルであって価値の測定値ではない。
- 採否の閾値は起動側が持つ。ここでは採点だけを返す。
