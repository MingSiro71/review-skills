# 採点基準: 規約

**対象**: 観点5（明文ルールとの照合）。および観点7 のうち、テストコードとテストデザイン
ドキュメントの記述の対応のずれ。後者の照合先はテストデザインドキュメントの記述そのもの。

## 採点

「**その指摘を落としたとき、誰が、いつ、どんなコストを払うか**」を言葉で書かせた上で、
そのコストの大きさを下の5水準で採点する。

| 点 | 基準 |
| --- | --- |
| 0 | 明文ルールに記載がなく、書き手の裁量の範囲 |
| 25 | 明文ルールは推奨のものでルールを外れることに強い合理性がある |
| 50 | 明文ルールは推奨のもので、外れることが強い合理性をもつとは言えない。または、強制力のあるルールだが外れた方法に強い合理性がある |
| 75 | 明文ルールは強制力のあるもので、これを外れることが強い合理性をもつとは言えない |
| 100 | 明文ルールは強制力のあるもので、外れることに何ら合理性がない |

### 合理性

ルールに従ったときに想定される実装と、実際の実装を並べて比べる。
**実際の実装が上回っていれば合理性があり、上回る幅がそのまま合理性の強さになる。**
**ルールに従っていること自体はメリットに数えない**（数えると、従った側が常に上回ることになる）。
書き手がどう考えたかを推測するのではなく、2つの実装を比べて判定する。

## 二重確認（この基準だけの手順）

引用されたルールの**本文を実際に読み**、その記述が本当にこの件を明示しているかを確認する。
明示していなければ却下する。**引用できないものは75以上にならない。**

## 守ること

- **ほかの採点基準と比較しない。** この基準の中での強さだけを測る。
- **深刻度の自己申告を採点に使わない。** 高/中/低 は書き手のラベルであって価値の測定値ではない。
- 採否の閾値は起動側が持つ。ここでは採点だけを返す。
