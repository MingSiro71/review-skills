# 観点4: 変更を入れた値の妥当性

- **入力**: diff ＋ 周辺
- **採点**: `scoring/bug.md`

## 担当

変更された値・定数・初期値・フォールバック・閾値について、**直した場所が正しいか**。

- より根源の箇所で直すべきものを、末端で押さえていないか
- 逆に、末端で足りるものを根源に手を入れて影響範囲を広げていないか
- その値がどこから来て、どこで使われるか。同じ値が他の場所にも書かれていないか
- フォールバックが、実際には存在するデータに対して誤った値を作らないか
  （「無ければ0」が、値が取れなかっただけの状態に0を与えていないか）

## 必ず示すこと

末端で直したことが問題だと主張するなら、根源で直さなかったことで壊れる具体的な入力を示す。
「本来はもっと上流で直すべき」という一般論だけでは失敗シナリオが書けない。

## 担当外

値の読みにくさ・命名は観点8。値がルールに反しているなら観点5。
